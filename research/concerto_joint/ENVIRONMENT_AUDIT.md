# 进一步环境审计：三项阻塞问题

> 历史阶段记录。v4后续被发现还有规则偏差，当前没有活动联合模型；现状见 [ALIGNMENT_20261108.md](ALIGNMENT_20261108.md)。
> 本文记录旧 `joint_v3_prices_clean` 的缺陷证据。当前修复及新运行见 [ENVIRONMENT_FIX.md](ENVIRONMENT_FIX.md)；旧权重继续作废，旧证据不覆盖。

价格修复和张量价格域审计仍然成立。但进一步复核发现下列联合适配层错误，**当前 joint_v3_prices_clean 不应推荐使用，修复环境后需重新生成标签和训练**。这不是对普通 beta 原始训练的指控。

## 1. 音符事件选项没有真正进入合法动作

`JointEpisode._sync()` 把 10701–10708 等选项放进 `eventOptions`，但复用内核的 `legal_actions()` 仍只遍历冻结的 `predictive` 子集。因此事件 107 即使有完整可见选项和足够音符，实际仍只有 `SKIP_EVENT`；108 也只剩 10809，无法选择添加的音符购买。

这说明模型实际上没有学到声称已暴露的那些音符事件选择。复现使用显式可见的已知选项，目的是检查适配层，不是声称真实游戏每次展示全部选项。

## 2. 普通潜能目标下的动作剪枝不适用于联合目标

内核 `DOMINANCE` 会在普通目标下删除被支配选项。联合层随后才扣除音符成本，顺序错误。

- 10301 需要五个音符，但底层先删除了 10302 和跳过；音符为零时，联合层再删掉 10301，最终动作集合为空。
- 音符足够时，也只剩“消耗五个音符换钱”，无法选择保留音符。
- 104 中消耗十音符的免费潜能，会使付金币但保留音符的选项提前被删。加入音符价值后，原来的支配关系不成立。

需要在联合环境中构造完整的可见、支付得起的动作集合，再执行转移；不能把普通目标的剪枝结果当成联合合法动作。

## 3. 音符商品独立定价破坏整架折扣约束

按已确认的价格修复映射读取原始日志：**1,331 次完整货架观测，每次都是四个折扣位**；复用内核本身也先在八格中选择四个折扣位。

当前联合层保留内核饮料后，独立从音符边际价格分布补剩余格，未保持整架相关性。固定配置／种子测试的 80 家首店中：四折扣位 27 家，其他 53 家出现一至七个折扣位。

这会改变可负担商品与金币分配，不能只修价格数值后就认为商店转移已与数据对齐。需要联合生成整架折扣，再根据商品类型确定价格。

## 本轮没有确认的问题

- 音符数量只出现五枚装 3,694 条、十五枚装 1,078 条，未发现其他非法数量。
- 1,331 个记录货架标识未重复；这不等于证明真实商店／交易独立，标识有推断成分。
- 忽略展示名称、按目标数值、技能集合、辅助供给和塔类型复核，训练／开发／测试配置交集均为零。

## 仍需实测确认的假设

战斗音符数量和分布、终局十五次调整的合法性与时机、部分“音符或治疗”事件的分支，以及用协奏等级总和代理实战收益，仍未由完整音符轨迹验证。

先前十八项检查主要覆盖价格、状态和数值一致性，没有覆盖上述事件动作集合与整架折扣约束。通过这些检查不代表完整模拟环境正确。

机器证据见 [environment_audit_v3.json](data/environment_audit_v3.json)。不需要原始日志即可复现实现问题：

```bash
python research/concerto_joint/audit_environment.py
```

该诊断在发现问题时返回退出码 1，修复后应返回零。历史输出保存在上面的 JSON；执行命令检查当前实现，不会覆盖历史证据。如有原始日志，可加 `--observations <path>` 重算完整货架统计；公开审计只保存计数和源文件哈希，不上传玩家记录。
